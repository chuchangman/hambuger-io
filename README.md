# 🍔 진상 고객 햄버거 가게 (3D)

**3D 1인칭 협동 요리 게임 + Gemini 진상 손님.** 3~5명이 브라우저로 같은 가게에 들어갑니다.

역할 구분은 없습니다. **누구나 손님과 대화하고, 누구나 요리합니다.**
말이 안 통하는 손님에게서 진짜 주문을 캐내 주문패드에 적고,
다 같이 주방을 뛰어다니며 제한 시간 안에 버거를 만들어 서빙하세요.

> 핵심은 버거를 빨리 만드는 게 아니라
> **"이상한 고객의 요구를 얼마나 정확한 주문으로 변환할 수 있는가"** 입니다.

---

## 빠르게 시작하기

**한 명(방장)만** 아래를 실행합니다.


```bash
npm install
npm start
```

터미널에 **팀원에게 보낼 주소가 그대로 출력**됩니다.

```
  📡 팀원에게 이 주소를 보내세요 (같은 Wi-Fi / 같은 공유기)
  ➜ http://70.12.247.229:3210 (Wi-Fi)
```

팀원은 그 주소를 브라우저에 붙여넣기만 하면 됩니다. **설치할 것 없습니다.**
한 명이 **새 가게 열기** → 나머지는 **방 코드 4글자**로 입장 → 방장이 **라운드 시작**.

### 다른 네트워크에 있는 팀원까지

```bash
npm run share
```

Cloudflare 임시 터널로 `https://xxx.trycloudflare.com` 공개 주소를 만들어 줍니다.
계정·로그인 필요 없고, 창을 닫으면 주소도 사라집니다.
(cloudflared 가 없으면 자동으로 내려받습니다. 첫 실행은 1~2분 걸릴 수 있습니다.)

### 팀원이 못 들어올 때

거의 항상 **방화벽**입니다. 방장 PC에서 관리자 PowerShell 로 한 번만:

```powershell
netsh advfirewall firewall add rule name="Burger 3210" dir=in action=allow protocol=TCP localport=3210
```

그 외 확인할 것:
- 방장과 팀원이 **같은 Wi-Fi** 인가 (게스트망은 서로 못 봅니다)
- `http://` 로 시작하는가 (`https://` 아님)
- 포트 `:3210` 까지 붙였는가

WebGL을 지원하는 최신 브라우저면 됩니다. three.js는 `node_modules`에서 직접 서빙하므로 CDN이 필요 없습니다.

## Gemini 손님 연결하기

API 키 **없이도** 규칙 기반 오프라인 손님으로 바로 플레이됩니다.
매번 다른 손님을 만나려면 Google AI Studio 키를 넣으세요.

### 1. 키 발급

[aistudio.google.com/apikey](https://aistudio.google.com/apikey) → **Create API key**

### 2. `.env` 파일 만들기

```bash
cp .env.example .env
```

**`.env`** 를 열어 키를 붙여넣습니다. **따옴표 없이**, 앞뒤 공백 없이 씁니다.

```
GEMINI_API_KEY=여기에_발급받은_키
```

> ⚠️ **`.env.example` 이 아니라 `.env` 에 넣으세요.**
> `.env` 만 `.gitignore` 되어 있습니다. `.env.example` 에 실제 키를 쓰면 커밋 시 유출됩니다.

### 3. 연결 확인

```bash
npm run check:llm
```

성공하면 `✅ 연결 성공` 이 뜹니다.
실패하면 원인(키 오류 / 권한 / 할당량 / 모델명)과 **이 키로 쓸 수 있는 모델 목록**을 같이 알려줍니다.

### 4. 서버 재시작

```bash
npm start
```

시작 로그에 `LLM : Gemini (gemini-flash-lite-latest) 사용` 이 뜨면 적용된 것입니다.

### 모델 선택 (중요)

기본값은 **`gemini-flash-lite-latest`** 입니다. 실측 기준:

| 모델 | 응답 속도 | 무료 등급 | 게임 적합성 |
|---|---|---|---|
| **`gemini-flash-lite-latest`** (기본) | **~1.3초** | 넉넉함 | ✅ |
| `gemini-flash-latest` (=3.7-flash) | ~16초 | **분당 5회** | ❌ 한 라운드도 못 버팀 |
| `gemini-2.5-flash` 등 고정 버전 | — | — | ❌ 신규 키에서 404 |

한 라운드에 손님 대사·받아쓰기·평가로 6~10회를 호출하므로 **분당 요청 한도가 실제 병목**입니다.
버전을 고정하지 않고 `-latest` 별칭을 쓰는 이유는, 구글이 특정 버전을 신규 사용자에게 막으면
`404 no longer available to new users` 로 갑자기 깨지기 때문입니다.

바꾸려면 `.env` 에 `GEMINI_MODEL=모델이름` 을 추가하세요.
쓸 수 있는 이름은 `npm run check:llm` 이 알려줍니다.

### 자주 겪는 문제

| 증상 | 원인 / 해결 |
|---|---|
| `API key not valid` | 키 오타, 따옴표·공백 포함. AI Studio에서 다시 복사 |
| `403 / SERVICE_DISABLED` | 해당 Google Cloud 프로젝트에서 Generative Language API 비활성 |
| `429 / quota` | 분당 요청 한도 초과. 더 가벼운 모델(`gemini-flash-lite-latest`)로 바꾸세요 |
| `404 not found` | 모델명이 이 키에서 안 됨 → `npm run check:llm` 의 목록에서 고르기 |
| 게임은 되는데 손님이 단조로움 | 키가 안 잡혀 오프라인 손님으로 도는 중. 시작 로그 확인 |

호출이 실패해도 **자동으로 오프라인 손님으로 대체**되므로 게임이 멈추지는 않습니다.

키는 서버에서만 쓰이며 브라우저로 내려가지 않습니다. `.env` 는 `.gitignore` 에 들어 있습니다.

## 조작법

| 키 | 동작 |
|---|---|
| **W A S D** | 전후좌우 이동 |
| **Shift** | 달리기 |
| **Space** | 점프 |
| **마우스** | 시점 (캔버스를 클릭하면 마우스가 잠깁니다) |
| **E** / 좌클릭 | 조준한 대상과 상호작용 |
| **Q** | 손에 든 재료 버리기 |
| **R** | 채소·소스 **양** 바꾸기 (조금 / 보통 / 많이) |
| **C** | 손님과 대화창 열기 (어디서나) |
| **B** | 주문패드 열기 (어디서나) |
| **Esc** | 창 닫기 / 마우스 잠금 해제 |
| **좌클릭** (빗자루 든 상태) | 🧹 **휘두르기** |

화면 가운데 조준점을 물건에 맞추면 무엇을 할 수 있는지 문구가 뜹니다.
**손에는 한 번에 하나만** 들 수 있습니다.

### 점프

**Space** 로 뜁니다. 최고 0.80m, 체공 0.5초.
**달리면서 뛰면 관성이 실려 앞으로 약 3.1m 날아갑니다** — 공중에서는 방향을 조금밖에 못 바꿉니다.
조리대를 빙 돌지 않고 질러갈 때, 그리고 빗자루를 피할 때 씁니다.

### 🧹 빗자루 난투

플레이어끼리 **서로 통과할 수 없습니다.** 좁은 주방에서 길을 막는 것부터가 훼방입니다.

가게에 빗자루가 **3개** 놓여 있습니다. **E** 로 집고 **Q** 로 제자리에 돌려놓습니다.

- **좌클릭으로 휘두릅니다.** 사거리 2.6m, 정면 ±70도, 쿨다운 0.65초 (별도 알림 없이 조용히 날아갑니다)
- 맞은 사람은 **포물선을 그리며 날아갑니다** (최고 0.56m, 약 3.7m 비행)
- 날아가는 동안 **들고 있던 재료를 놓칩니다**
- 단, **빗자루를 들면 재료를 못 듭니다.** 훼방에는 대가가 따릅니다
- 협상 중에도 쓸 수 있습니다

거리와 쿨다운은 서버가 다시 검사하므로 클라이언트를 고쳐도 뚫리지 않습니다.
빗자루를 든 채로 나가거나 라운드가 끝나면 자동으로 제자리에 돌아옵니다.

## 가게 구조

바닥이 색으로 나뉘어 있고, 화면 아래 **위치 표시**가 지금 어느 구역인지 알려줍니다.

| 구역 | 하는 일 |
|---|---|
| 🔴 **카운터** | 손님 응대 · 주문패드 · 서빙 창구 |
| 🟢 **주방** (좌·우 벽) | 재료 냉장고 / 그릴·토스터·소스 |
| 🔵 **조립대** (가운데 섬) | 재료를 아래에서 위로 쌓기 |

### 만드는 순서

1. **🧊 냉장고**에서 재료를 집습니다. (E)
2. 재료 종류에 따라 손질합니다.
   - 패티 · 베이컨 · 계란 → **🔥 그릴**에 올리고, 초록 구간에서 꺼냅니다.
   - 번 → **🍞 토스터** (주문서가 "안 구움"이면 그냥 접시로 직행)
   - 채소 → **R**로 양을 정하고 **🔪 도마**에 올린 뒤 **E 연타**로 썹니다. 다 썰면 자동으로 손에 들어옵니다.
   - 치즈 → 손질 없이 바로 사용
   - 소스 → **R**로 양을 정하고 디스펜서에서 짭니다.
3. **🍔 조립대**에 아래에서 위 순서로 쌓습니다. (빈손으로 E를 누르면 맨 위 재료를 되돌립니다)
4. **🛎️ 서빙 창구**에서 E.

생재료를 그대로 접시에 올릴 수는 없습니다. 안 구운 고기와 안 썬 채소는 거부됩니다.

**쌓는 순서도 점수에 들어갑니다.** 표준 순서는 아래와 같습니다.

```
아래 번 → 패티 → 치즈 → 베이컨 → 계란 → 양상추 → 토마토 → 양파 → 피클 → 소스 → 위 번
```

순서가 하나 어긋났다고 뒤가 전부 0점이 되지는 않습니다. 최장 공통 부분수열로 채점하므로
**빠뜨리거나 뒤바뀐 만큼만** 깎입니다.

## 한 라운드의 흐름

```
손님 등장 → 대화로 주문 캐내기 → 주문 확정 → 다 같이 조리 → 서빙 → 평가
```

라운드 시간은 방장이 대기실에서 고릅니다.

| 진행 속도 | 주문 받기 | 조리 | 언제 |
|---|---|---|---|
| 여유 | 180초 | 180초 | 처음 해보는 사람과 |
| **보통** (기본) | 120초 | 120초 | 기본 |
| 긴박 | 90초 | 90초 | 손이 바쁩니다 |

### 이 게임의 핵심 장치: 숨겨진 진짜 주문서

서버는 라운드 시작 시 **손님이 진짜 원하는 주문**을 몰래 생성합니다.
이 값은 결과 화면 전까지 **어떤 클라이언트에도 전송되지 않습니다.**

| | 만드는 주체 | 볼 수 있는 사람 |
|---|---|---|
| 😀 **진짜 주문** | 서버가 몰래 생성 | 손님(LLM)만 |
| 📝 **주문서** | 플레이어들이 함께 작성 | 전원 |
| 🍔 **실제 버거** | 플레이어들이 제작 | 손님이 먹음 |

주문패드는 **공용**입니다. 아무나 고칠 수 있고, 아무나 확정할 수 있습니다.
잘못 적으면 그대로 만들게 되고, 손님은 자기가 원한 것과 비교해 화를 냅니다.
결과 화면에서 이 셋을 나란히 놓고 어디서 어긋났는지 보여줍니다.

## 점수 체계

| 항목 | 비중 | 무엇을 재나 |
|---|---|---|
| 🎯 **최종 정확도** | 32% | 진짜 주문 ↔ 실제 버거 — 손님이 실제로 겪은 결과 |
| 📝 **주문 정확도** | 20% | 진짜 주문 ↔ 주문서 — 대화로 얼마나 잘 캐냈나 |
| 😤 **고객 만족도** | 18% | LLM이 캐릭터를 유지한 채 매기는 점수 |
| 🔥 **조리 상태** | 12% | 구운 재료들의 평균 품질 |
| 🥞 **조립 순서** | 10% | 표준 순서와 얼마나 맞게 쌓았나 |
| ⏱️ **제작 시간** | 8% | 절반 안에 끝내면 만점 |

이와 별개로 **👨‍🍳 제작 정확도**(주문서 ↔ 실제 버거)도 표시됩니다.
"주문서대로는 만들었는데 주문서가 틀렸다"를 증명할 때 쓰세요. 총점에는 들어가지 않습니다.

**인내심 게이지**는 시간이 갈수록 줄고, 조리 중 손님에게 말을 걸면 회복됩니다.
성격 급한 손님은 두 배로 빨리 닳습니다.

## 프로젝트 구조

```
server/
  index.js   Express + Socket.IO, 방 관리, 1초 틱, 위치 스냅샷(10Hz)
  game.js    Room 상태 머신, 손(holding) 기반 주방 액션, 조리 품질 · 조립 순서 · 점수
  menu.js    재료 정의, 고객 페르소나, 주문 생성·변형
  llm.js     Gemini REST 호출 (대사/받아쓰기/평가) + 오프라인 규칙 기반 대체
scripts/
  check-llm.js  Gemini 키·모델 점검 (`npm run check:llm`)
public/js/
  main.js    엔트리 — 렌더 루프
  net.js     소켓 + 공유 상태
  world.js   three.js 씬 (식당, 바닥 구역, 스테이션, 조리 시각화, 아바타)
  player.js  1인칭 컨트롤러 (WASD, 마우스룩, 충돌, 조준 상호작용)
  ui.js      HUD · 위치 표시 · 대화/주문패드 오버레이 · 대기실 · 결과
test/
  smoke.js   3인 플레이 전체 흐름 자동 검증 (`npm test`)
  broom.js   빗자루 난투 검증 (`npm run test:broom`)
```

Gemini는 SDK 없이 REST(`generativelanguage.googleapis.com`)를 Node 내장 `fetch`로 호출합니다.
의존성은 `express` · `socket.io` · `three` · `dotenv` 넷뿐입니다.

다른 플레이어는 3D 안에서 **아바타로 보이며**, 손에 든 재료까지 실시간으로 보입니다.

### 자동 검증

서버를 켠 상태에서:

```bash
npm test
```

조립 순서 채점(정확·역순·누락·빈접시)을 먼저 단위 검증하고,
3명이 접속해 대화 → 주문 → 조리 → 서빙 → 평가까지 한 라운드를 자동으로 돌립니다.
역할 제한이 없는지, 손 규칙이 지켜지는지, 진행 속도가 반영되는지,
세 명이 동시에 다른 스테이션을 쓸 수 있는지, 위치 동기화가 되는지 확인합니다.

---

## 손보기 좋은 지점

| 하고 싶은 것 | 고칠 곳 |
|---|---|
| 라운드 시간 프리셋 | `server/game.js` 의 `PACES` |
| 표준 조립 순서 | `server/game.js` 의 `LAYER_ORDER` |
| 굽기 난이도 조절 | `server/menu.js` 의 `INGREDIENTS` — `target`, `burnt`, `tol`(관대할수록 크게) |
| 바닥 구역 범위 | `public/js/world.js` 의 `ZONES` |
| 빗자루 위력·사거리·쿨다운 | `server/game.js` 의 `HIT_RANGE`, `HIT_COOLDOWN`, `KNOCKBACK` |
| 점프 높이·중력·공중 조작 | `public/js/player.js` 의 `JUMP_V`, `GRAVITY`, `AIR_CONTROL`, `HIT_LAUNCH` |
| 빗자루 개수·위치 | `server/game.js` 의 `BROOM_RACKS` / `world.js` 의 `BROOM_SPOTS` |
| 이동 속도 / 시야각 | `public/js/player.js` 의 `SPEED`, `RUN` / `world.js` 의 카메라 `fov` |
| 새 고객 유형 | `server/menu.js` 의 `PERSONAS` 배열에 항목 추가 |
| 점수 비중 | `server/game.js` 의 `applySatisfaction` |
| 그릴/도마 개수 | `server/game.js` 의 `GRILL_SLOTS`, `TOASTER_SLOTS`, `CHOP_BOARDS` |

## 참고

- 기본 포트는 **3210** 입니다. (`.env` 의 `PORT` 로 변경 가능)
- 방장이 나가면 남은 사람 중 한 명이 자동으로 방장이 됩니다.
- 방은 모든 인원이 나가면 자동으로 사라집니다.
- 브라우저 탭을 다른 창으로 가리면 렌더 루프가 멈춥니다(브라우저 기본 동작). 돌아오면 즉시 재개됩니다.
